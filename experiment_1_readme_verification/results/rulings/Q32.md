# Q32 — "pruned for publication with a signed manifest — see PRUNED.md for what was removed and how to restore any of it from history"

Adjudication: model-made (delegated by owner).

## Ruling
**contradicted** on "signed"; verified on existence and restorability.

## Basis
- Existence: `walkthrough/paper_pipeline/phase_1/resolve_runs/graph_v2/PRUNED.md` exists at the linked path (135 lines; header "# PRUNED.md — evidence-prune manifest (2026-08-30)").
- Restorability: `PRUNED.md:4-6` — "NOTHING IS LOST: full git history is retained, and each entry pins the exact content by git object id (tree/blob sha at the pre-prune commit). To restore any entry: `git checkout <pre-prune-commit> -- <path>`." Every 40-hex object id in the file resolves: `git cat-file -e` on all distinct hash-like tokens → 85 ok, 8 "BAD" — and the 8 are not object ids (7 date prefixes `20260810`…`20260818` and the config hash `c24c4c05` in a filename). Two entries are marked "untracked-or-file | 0 | 0" (no object id, nothing to restore).
- Signature (inventory definition: detached signature, signer-attested checksum of the manifest, or explicit signer line; git object ids alone do NOT satisfy): none.
  - `grep -in "sign\|gpg\|sha256\|checksum" PRUNED.md` → no hits; the file has no signer line.
  - No detached signature file: `find . -name '*.sig' -o -name '*.asc' -o -name 'PRUNED*'` → only `PRUNED.md`.
  - Commits are unsigned: `git log --format='%h %G? %GS' -3 -- PRUNED.md` → `6d01415b N`; whole history `%G?` → 654 N, 2 E (no G).
- The manifest is content-addressed (tree/blob shas), which is what the README's "signed" appears to mean; under the inventory's definition that is not a signature.

## Arms
Both arms ruled contradicted on the signature and verified existence/restorability; both right, substance agreement.

No.
