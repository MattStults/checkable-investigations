# Q28 — "failed every separability test once a matched random-partition null was run against it"

Adjudication: model-made (delegated by owner).

## Ruling
**contradicted** on the quantifier: the record shows one separability test run against a matched random-partition null (it failed); the ontology's other separability results were never null-tested — they were downgraded by a value-reuse audit, a different instrument.

The question: how many separability tests were run against a matched null, and did each fail?

## Basis
- Separability tests in the record for the query-class ontology: (a) `ITERATION_NOTES.md:767` (0038) "separability 94/100 both seats identically" over definitions; (b) `:783-790` (0039) "Defensible numbers: dimension-set separability 0.37-0.40 (definitions) / 0.85 (nodes)" — downgraded by "the vacuousness audit"; (c) `:817-822` (0041) "MID LEVEL = separability 1.00 on BOTH seats at 0.57-0.58 vocabulary reuse".
- Null runs in the record: exactly one. `ITERATION_NOTES.md:838-840` (0042) — "(F1) random 4-bucket partition => sep 1.00 in 299/300 trials, reuse 1.00 — the registered pass condition is satisfiable by noise"; `RETRANS_REVIEW_DISPOSITION.md:10-15` — "F1 NULL MODEL: a content-free random 4-bucket-per-family partition of the leaf vocabulary achieves separability 1.00 in 299/300 seeded trials ... dominating the real mid lattice (1.00 sep / 0.57-0.58 reuse) on the census's own pass condition." That null was run against test (c) only.
- The record says so itself: `ITERATION_NOTES.md:849-851` — "I ran a vacuousness audit (value-reuse) but never a NULL MODEL"; `:853-855` — "BINDING RULE ADOPTED ...: every separability/representability claim ships with a seeded matched-granularity random-partition null" (adopted after, and applied to none of the earlier tests). `grep -n -i null ITERATION_NOTES.md` hits only lines 849-904 (0042/0043); no null appears in 0038, 0039 or 0041.
- Denominator: 3 separability tests; null-tested: 1; failed against the null: 1.

"Every separability test" is therefore not what the record shows; one test failed against a null, and the 0038/0039 figures fell to a reuse audit, not a null.
